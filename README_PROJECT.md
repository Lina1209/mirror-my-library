# ©Mirror — личная библиотека и читалка

## Возможности
- Импорт и локальное хранение FB2, FB2.ZIP, EPUB, PDF, DOCX, XLSX, XLS, CSV, TXT и HTML.
- Чтение EPUB, FB2, PDF, TXT, CSV, HTML, DOCX и таблиц Excel.
- Для PDF: извлечение встроенного текстового слоя; если страница сканированная — OCR (русский + английский) с выгрузкой распознанного текста в TXT.
- Полноэкранный режим, перелистывание касанием влево/вправо, кнопки навигации, размер шрифта и сохранение прогресса.
- Ночная тема с сохранением выбора.
- Отдельный экран библиотеки и отдельный экран чтения.
- Поиск, избранное, фильтры, закладки, скачивание оригинала.
- PWA-оболочка и локальная база IndexedDB.

## Запуск
Откройте GitHub Pages или запустите проект через локальный HTTP-сервер. Для EPUB, PDF, DOCX, XLS/XLSX и OCR требуются CDN-библиотеки и интернет при первом использовании.

## Ограничения и важные замечания
- Старый бинарный формат Word .DOC не поддерживается браузерным чтением; сохраните его как .DOCX и добавьте повторно.
- OCR сканированного PDF формирует текстовый файл TXT. Он не восстанавливает исходную вёрстку PDF, таблицы, подписи и расположение изображений один-в-один. Для юридически/архивно точной копии сохраняйте исходный PDF.
- Качество OCR зависит от разрешения, контраста, наклона страницы и языка. Для другого языка потребуется добавить соответствующую языковую модель.
- Внешние библиотеки и OCR загружаются с CDN; без интернета эти функции могут быть недоступны.
- Книги и прогресс хранятся только в текущем браузере/устройстве. Очистка данных браузера может удалить библиотеку; облачной синхронизации и резервной копии пока нет.
- Для HTML применяется очистка опасной разметки. Не открывайте неизвестные файлы как доверенные документы.
- Для полноценной проверки нужны реальные тестовые файлы разных форматов, включая сканированные PDF, и проверка на Android и настольном браузере.

## Структура
- `index.html` — интерфейс
- `css/styles.css` — оформление
- `js/app.js` — логика библиотеки и читалки
- `js/db.js` — IndexedDB
- `js/parsers.js` — парсеры FB2/HTML и метаданных
- `service-worker.js` — кэширование приложения

## Перевод интерфейса через Google Cloud Translation

В приложении добавлен отдельный переводчик интерфейса: переводит подписи, меню, кнопки, подсказки и элементы страниц библиотеки. Содержимое книг внутри читалки, названия книг в карточках и данные пользователя не переводятся. Выбор языка и адрес сервиса сохраняются на устройстве; переводы кэшируются локально.

Для безопасной работы нужен небольшой серверный посредник (Cloudflare Worker). **Не вставляйте Google API key в HTML, JavaScript, GitHub или настройки приложения.**

### Однократная настройка Google Cloud
1. Создайте проект в Google Cloud Console.
2. Включите Cloud Translation API (Basic v2) и подключите платёжный аккаунт.
3. Создайте API key. В ограничениях ключа выберите только Cloud Translation API. Не публикуйте ключ.
4. Настройте бюджет и квоты, чтобы контролировать расходы.

### Развёртывание защищённого посредника
1. Создайте Cloudflare Worker и вставьте содержимое файла `worker/google-translate-worker.js`.
2. В настройках Worker → Variables and Secrets добавьте секрет `GOOGLE_TRANSLATE_API_KEY` со значением вашего Google API key.
3. Добавьте переменную `ALLOWED_ORIGIN` со значением origin вашего сайта (например, `https://ВАШ-АККАУНТ.github.io`, без пути и завершающего слеша). Если сайт открывается с другого домена, укажите его точный origin.
4. Опубликуйте Worker и скопируйте его адрес вида `https://имя.workers.dev`.
5. В ©Mirror нажмите «🌐 Перевод», вставьте адрес Worker, выберите язык и нажмите «Перевести интерфейс».

Worker принимает только небольшие пакеты текста и проверяет Origin. CORS не является полноценной защитой от злоупотребления: обязательно ограничьте API key только Cloud Translation API и задайте дневные квоты/бюджет в Google Cloud. Не используйте `ALLOWED_ORIGIN=*` для публичного приложения.

### Стоимость и ограничения
Google Cloud Translation Basic предоставляет кредит на первые 500 000 символов в месяц (условия и применимость кредита могут меняться); далее применяется тариф Google. Проверяйте актуальную стоимость в официальном прайс-листе. Для перевода интерфейса отправляются только текстовые элементы приложения, не содержимое читалки. Для работы перевода требуется интернет.

Официальная документация:
- https://docs.cloud.google.com/translate/docs/setup
- https://docs.cloud.google.com/translate/docs/authentication
- https://cloud.google.com/products/translate/pricing


## Редактирование PDF с сохранением исходной страницы

В PDF-читалке доступны инструменты поверх исходной страницы: добавление текста (с выбором размера и цвета), перо, маркер, ластик для собственных пометок, белая плашка для закрытия области, вставка изображения и отмена последнего действия. Пометки сохраняются локально в библиотеке отдельно от исходного PDF. Кнопка «Сохранить PDF» создаёт новую копию с наложенными изменениями, сохраняет её в библиотеке и скачивает на устройство; исходный файл не перезаписывается.

**Важно:** это редактор слоёв/аннотаций, а не полноценное удаление или переписывание исходного PDF-текста. Белая плашка визуально закрывает участок, но не удаляет скрытый под ней текст из структуры PDF. Текст и изображения добавляются поверх страницы; вставленное изображение размещается по центру. Перемещение, масштабирование, выбор и повторное редактирование уже добавленных объектов пока не реализованы. Исходный слой страницы остаётся нетронутым, поэтому внешний вид оригинала сохраняется за пределами наложенных областей. Для настоящего изменения текста, таблиц и исходных изображений лучше редактировать исходный DOCX/ODT или другой файл-источник и затем экспортировать его в PDF.


## Студия документов — OCR и импорт/экспорт офисных форматов

- DOCX: импорт через Mammoth с преобразованием в редактируемую HTML-структуру; экспорт в DOCX поддерживает обычные абзацы, заголовки, списки, базовое начертание и простые таблицы. Сложная вёрстка, колонтитулы, поля, плавающие объекты, встроенные изображения и специальные стили могут не сохраниться.
- XLSX/XLS/CSV: импорт первого листа в редактируемую таблицу; экспорт таблицы из редактора в XLSX. Многостраничная структура книги, формулы, стили ячеек и прочие листы не переносятся в текущем редакторе.
- Исходные файлы не перезаписываются. Перед заменой оригинала сравните экспортированную редакцию с исходником.

### Студия документов — OCR и базовое редактирование

- OCR сканированных PDF и изображений через Tesseract.js; поддерживаются языковые модели русского, английского, казахского и ряда других языков.
- Для PDF сначала извлекается доступный текстовый слой, сканированные страницы распознаются как изображения.
- Результат можно редактировать (жирный, курсив, заголовки, абзацы), сохранять как новую HTML-редакцию в локальную библиотеку, скачивать TXT/HTML или печатать/сохранять через системный диалог как PDF.
- Исходник не перезаписывается. OCR требует интернета для загрузки движка и языковых данных.
- Ограничение: точное восстановление исходных шрифтов, таблиц, изображений и вёрстки не гарантируется. Полноценный импорт/экспорт DOCX/ODT/RTF и табличных форматов и реконструкция макета — следующие этапы.

### PDF: распознавание и исправление строк на странице

В PDF-редактор добавлен OCR текущей страницы с выбором распознанной строки. После распознавания можно выбрать строку, исправить её текст и наложить исправленную строку на белую маску в приблизительно том же месте. Результат сохраняется как отдельная PDF-копия вместе с другими визуальными аннотациями.

Это визуальная реконструкция выбранной строки, а не редактирование исходного текстового объекта PDF: исходный текст под маской может оставаться извлекаемым. Подбор шрифта, размера и ширины приблизительный; сложные шрифты, поворот текста, колонки и точное сохранение межстрочных интервалов не гарантируются. Не используйте этот режим для безопасного удаления конфиденциальных данных. Для юридически значимого или конфиденциального удаления нужна настоящая PDF-redaction, удаляющая содержимое из файла.


### Изображения в PDF: размещение и изменение размера

Вставленные изображения теперь являются отдельными объектами: их можно перетаскивать пальцем или мышью, а размер менять за угловой маркер. Положение и размеры сохраняются для каждой страницы в локальной библиотеке и включаются в экспортируемую PDF-копию. Старые изображения, ранее сохранённые как единый плоский слой, отдельно перемещать нельзя.


### Исправленный OCR-текст: перемещение и изменение размера

После выбора распознанной строки и ввода исправления новый текст теперь создаётся отдельным объектом. Его можно перемещать пальцем или мышью, а размер изменять угловым маркером. Положение, размеры и текст сохраняются в локальной библиотеке и включаются в новую PDF-копию. Подбор шрифта остаётся приблизительным; исходный текст под белой маской может оставаться извлекаемым.


### Настройка оформления исправленного текста PDF

Для выбранной OCR-строки доступны семейство шрифта (Arial, Georgia, Times New Roman, Verdana, Courier New), цвет, жирное и курсивное начертание, белый или прозрачный фон. Выберите строку на странице, измените параметры на панели — настройки применятся и сохранятся. Экспорт страниц с правками формирует растровый слой страницы, поэтому на изменённых страницах исходный текст может перестать выделяться как текст. Неизменённые страницы остаются исходными страницами PDF. Визуальное совпадение с оригинальной гарнитурой не гарантируется.


### Расширенное форматирование и управление таблицами в Студии документов

В редактор добавлены выравнивание абзацев (слева, по центру, справа, по ширине), маркированные и нумерованные списки, выбор семейства и размера шрифта, цвета текста и цветового выделения. Таблицы можно вставлять (3×3), добавлять и удалять строки и столбцы по текущей ячейке. DOCX-экспорт дополнительно переносит выравнивание абзацев, часть встроенного форматирования текста, границы и цвет заливки простых ячеек. Это улучшает сохранение простого макета. Объединения ячеек, ширина столбцов, высота строк, базовые границы и заливка таблиц дополнительно восстанавливаются из XML исходного DOCX (см. раздел «Сложные таблицы DOCX» ниже); плавающие объекты, колонтитулы, сложные стили темы и вложенные таблицы могут отличаться. Исходный файл остаётся нетронутым; результат сохраняется отдельной редакцией.


### Изображения и разрывы страниц в Студии документов

Импорт DOCX теперь сохраняет поддерживаемые встроенные изображения PNG, JPEG и GIF, если Mammoth передаёт их как встроенные data URI. Санитайзер пропускает только эти безопасные встроенные форматы; внешние картинки и активное содержимое не загружаются. При экспорте DOCX встроенные изображения помещаются в текстовые абзацы или ячейки таблиц и ограничиваются по ширине. Добавлена кнопка ручного разрыва страницы: маркер учитывается при экспорте DOCX и при печати/сохранении в PDF. Экспорт DOCX задаёт страницу A4 и базовые поля. Это улучшает перенос обычных документов, но не гарантирует исходную пагинацию, точные размеры и обтекание изображений, сложные объединённые ячейки, колонтитулы и плавающие объекты.


### Сложные таблицы DOCX — геометрия и экспорт

Для импорта DOCX дополнительно читается исходный `word/document.xml` внутри файла. Это позволяет восстановить объединения ячеек по горизонтали и вертикали, сетку и ширину столбцов, заданную высоту строк, повторяемые строки заголовков, запрет разрыва строки, заливку ячеек, границы, внутренние отступы и вертикальное выравнивание. Для чтения ZIP-контейнера используется JSZip, загружаемый по требованию; если библиотека недоступна, обычный текстовый импорт Mammoth остаётся доступен, но геометрия таблиц может не восстановиться.

Экспорт DOCX переносит доступные `rowSpan`/`colSpan`, ширину сетки столбцов, высоту строк, границы, заливку, отступы и вертикальное выравнивание через docx 8.5.0. HTML-редакция также сохраняет разметку объединений и геометрию. Это существенно улучшает перенос сложных таблиц, но не гарантирует идеальную копию всех Word-таблиц: плавающие таблицы, сложные стили темы, диагональные границы, вложенные таблицы и автоподбор ширины могут отображаться иначе. Оригинал не изменяется.
